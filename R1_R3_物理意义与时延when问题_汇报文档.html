0. 先把 α 的物理身份钉死（一切讨论的基础）

α 不是单一参数，是注入整个 CPPS 系统的"冗余资源水位"。它在代码里同时拨动 7 个旋钮：

通道代码位置α 的作用物理含义
① 电力支路容量cascadeLogic...:52(1+α)·P_branch输电线热稳定裕度 / N-k 容量储备
② 信息节点/链路容量cascadeLogic...:54-55(1+α)·betweenness路由器/链路缓存与处理能力
③ Φ_loss 并行冗余computeEtaPlus.mk_eff=1+α·(k_max−1), k_max=3PRP+G.8032+CIP-012 三路冗余
④ Φ_sat 死区computeEtaPlus.m:108-122τ_m0_eff=τ_m0+0.10·α高储备允许更宽 PMU 平滑窗
⑤ Φ_crit 临界阈computeEtaPlus.m:180-205τ_crit_max·(1+0.5α)频率/电压临界耐受时间
⑥ UFLS 切负荷上限cascadeLogic...:730-734shed_max_eff=0.85−0.20·αNERC PRC-006-5：高储备无需深切
⑦ τ_q 队列服务率cascadeLogic...:517-522μ_cc·(1+0.5·α)CC 算力配套提升
大白话比喻：α 就像写字楼的"冗余预算"——同时升级电梯（线路容量）、备用光纤（Φ_loss）、空调温控带宽（Φ_sat 死区）、消防响应窗（Φ_crit）、消防演习撤离深度（UFLS）、客服中心人手（μ_cc）。所以"α 越大→指标越好"是期望中的图像。

1. R1 vs α 柱状-折线图（Fig_Combined_R1）

📈 折线 左 Y 轴 / R1

R1 = 攻击+级联+时延都跑完之后，全网还能给多少比例的原始用户供电。
R1=1：完美抗住；R1=0.6：丢了 40% 负荷；R1=0：全网瘫痪。

为什么期望折线随 α 升高：α↑ → 线路热裕度变厚 + 通信路径变多 + UFLS 不过切 → 同一场攻击下被甩掉的负荷越来越少 → R1↑。

大白话：多花点钱买冗余，停电就少。

📊 柱子 右 Y 轴 / ΔR1 = R1no_delay − R1scenario

柱高 = "如果通信完全无时延，本场景下还能多救回多少比例的负荷"——也就是时延这个对手在当前 α 下偷走了多少肉。

为什么期望柱子随 α 单调降低：α↑ → η⁺→1（控制层"听话度"提高）+ Φ_loss 多备一路 + UFLS 不必过切 → 时延能造成的伤害被冗余一笔笔买回来 → 柱子越压越低。

大白话：钱花够了，时延就没东西可偷。

🚩 异常 1：no_delay 折线在 α=0 → α=0.1 莫名下降

结论：不是 bug，是 MC 噪声 + 临界非单调。

(a) 主因——蒙特卡洛抽样在 α 维度独立

rng(idxAlpha * 100000 + trial, 'twister');  % cascadeLogic:104
  • α=0 用一组 400 条故障路径
  • α=0.1 用另一组完全不同的 400 条故障路径

400 trials 下 R1 的 95% 置信区间约 ±0.02，任何 ≤0.02 的高低起伏都是噪声。

(b) 次因——临界系统的"延迟死亡"悖论：α 很小时（0→0.1），有些边缘线路从"立刻跳"变成"勉强活下来再被推爆"——后者反而引发更深的二次孤岛。这是文献里的 Braess-like cascading paradox。

怎么办（如果导师追问）：

  • 把 rng(idxAlpha*100000+trial) 改成 rng(trial)，让所有 α 共享同一组随机故障序列；
  • 或把 trials 从 400 提到 1000+，置信区间收窄到 ±0.013。

🚩 异常 2：α=0.7 处柱子反弹

结论：是真实的物理拐点，不是 bug——"α 双刃剑"在此暴露。

机制：α 在 ④Φ_sat 死区上是反向作用——τ_m0_eff = 0.05+0.10·α，α↑ 把死区拉宽。这有物理依据（高储备允许更宽 PMU 平滑窗），但副作用是：

  • no_delay 场景：τ=0，死区放宽无影响 → R1 仍线性升
  • heavy 场景：到 α=0.7 时 ⑥UFLS shed_max_eff = 0.85−0.20×0.7 = 0.71，恰好是 cap 与"过切惩罚"切换的拐点。cap 不再咬合，heavy 的 φ_eff 改由 over-shed 主导，heavy 的 R1 在 α=0.7 邻域出现局部凹陷

两条曲线一直升 + 一条局部凹陷 → 差值（柱子）在 α=0.7 反弹。

诊断方法：

  1. 取 α=0.6/0.7/0.8 三个点的 delay_injection_log.ufls_phi_eff 时间序列对比
  2. 单独画 η⁺(α) 在 heavy 时延下的曲线，看 Φ_sat 是否在 α=0.7 反噬

修复（若想要严格单调）：把 tau_m0_alpha_gain 从 0.10 调小到 0.05；或把 ⑥shed_max α-下调速率从 0.20 改到 0.10。不破坏 α=0 严格回归。

2. R3 vs α 柱状-折线图（Fig_Combined_R3）

📈 折线 左 Y 轴 / R3

R3 = "调度员发出的出力指令 Pref，被实际执行成 Pactual 时偏了多少"——是控制层的"忠诚度"度量。
公式：R3 = √( Σ Pref·((Pactual−Pref)/Pref)² / Σ Pref )（容量加权 NRMSE）
R3 越小越好：0=完美执行，越大=指令被时延越扭曲。

类比：R1 是"还有没有电"，R3 是"电压频率稳不稳，机组听不听话"。R1 看量，R3 看质。

为什么期望折线随 α 下降：α↑ → η⁺→1 → Pactual = Pref·η⁺ → Pref → R3↓。

大白话：给控制层多备份，调度令就被忠实执行。

📊 柱子 右 Y 轴 / ΔR3 = R3scenario − R3no_delay

注意符号：因为 R3 是"越小越好"，柱定义反过来减，保证"正柱 = 该场景比 no_delay 更差"——视觉读法跟 R1 图一致。

柱高 = "时延把调度令污染到什么程度"——通信信道的"控制透明度"反指标。柱→0 信道对控制完全透明；柱很高，调度令"走样"严重。
为什么 R3 图比 R1 图"听话"：R1 经过 UFLS cap、孤岛跳闸等离散非线性环节，所以容易在某些 α 上不单调；R3 是连续的加权 NRMSE，直接耦合 η⁺，而 η⁺ 三个分量（Φ_loss/Φ_sat/Φ_crit）对 α 都是单调的。所以 R3 柱基本单调下降，没有 R1 那种 α=0.7 的反弹。

🔬 物理意义（理论依据，先证明图是对的）

R1 热图为什么第 1–2 轮最亮？

R1 逐轮拆开是：

R1(r) = [Lsurviving(r) / Linitial] × min(φglobal(r), φeff(r))

时延通过 η⁺ → φeff → R1。关键观察：

  1. 第 1 轮：Lsurviving(1) ≈ Linitial。任何 φeff 跌一分，直接按 1:1 权重砍 R1。
  2. 第 r 轮（r 大）：Lsurviving 已被前轮孤岛削掉 30–50%。同样大小的 φeff 跌幅，绝对作用到 R1 上的扣分被 Lsurviving 这个小系数稀释。
  3. τ 本身在第 1 轮也最大：因为通信网此刻最完整、路径最长 → n_hops 多 → Φ_loss 累积损耗最大、端到端 τ 基数最大。后续轮次通信节点被打掉，残存图反而更短，τ 反而变小。
理论一句话：时延的"惩罚力" = 通信层产生的 τ × 电力层暴露的 Pref 基数。两个量都在第 1 轮最大，所以 ΔR1 在 r=1 峰值。

大白话：第一轮就是"满负荷遇上满时延"——满院子人 + 消防车堵在路上，损失最惨。后面人都跑光了，你消防车多堵 10 分钟也没人可救。

R3 热图同理

R3 第 r 轮的加权基数 = Σ Pref(本轮在场机组)。第 1 轮机组最齐全 → 加权基数最大 → 同样 Pactual−Pref 偏差被最大权重放大。τ 又在第 1 轮最大 → R3 也是 r=1 峰值。

两张图的内在一致性

R1 看"宏观断电规模"，R3 看"微观控制忠诚度"，但两者都被同一物理事实驱动：第一轮是通信完整 × 负荷完整 × 攻击新鲜的"三者最大"乘积——这是黄金打击窗口。

🎨 大白话总结

"先发制人型伤害"：通信网最健全、负荷最齐全、控制器还没察觉异常的那一刻，恰恰是时延能下嘴最深的一刻。等到第 3、4 轮，"该死的早死了，能跑的早跑了"——剩下的小残系统，时延就算大也咬不动多少。

4. 能不能让第 2/3/4 轮成为"最伤害"的一轮？（设计问题）

现状：当前模型里 τ 是瞬时函数——每轮根据当时的通信子图算端到端时延，没有"积累"或"潜伏期"。τ 自然衰减 + Lsurviving 自然衰减，两者相乘 → 第 1 轮必然最重。

要把峰值移到第 k 轮，必须破坏"τ 单调衰减"或"L 单调衰减"中至少一个。可行方案：

方案物理动机实现位置难度
A. τ 排队累积
(推荐)		DDoS / NERC 文档化的 "secondary delay due to control center congestion"——CC 队列在前几轮逐步堆积，第 k 轮 ρ→1 才爆cascadeLogic...:493-552
把 ρ 改成 cumulative		中
B. APT 潜伏触发
(最易做对照)		高级持续威胁的恶意载荷在第 k 轮才激活τ 注入处加 round-gate：if r ≥ r_trigger then full τ else 0易
C. 协议超时重传雪崩TCP / IEC 61850 GOOSE 第 1 次丢包后下一轮重传 ×2，第 k 轮指数爆炸computeEtaPlus.m 加历史状态中
D. 控制器自适应失稳PMU/AGC 前几轮"以为还正常"，第 k 轮才意识到偏差并过激修正tau_crit_max(r) round 依赖中
E. 攻击者"先扰边缘后打骨干"第 1 轮只打信息层叶子，第 k 轮才打骨干修改 pickAttack_*高
🎯 推荐组合：A + B
  • A 最有物理依据 —— NERC PRC-002-2 / NASPI 都有真实记录的 CC 拥塞二次时延
  • B 最易做"控制实验"—— 一个参数 r_trigger 即可生成 4 张峰值在不同轮次的热力图，是论文里最有说服力的"我们能控制 WHEN"证据

📌 一句话钉死核心结论

R1 答 "what 损失" + R3 答 "how well 跟踪" + 两张热力图答 "when 最伤"。三者拼起来给出 CPPS 时延韧性的完整三维画像：损失多大、控制偏多远、伤害集中在何时。

α 是这三维画像的"投资输入"。当前实验显示：α 投入越多，三维画像中的"红区"都被压向 0；唯一的非单调点在 α=0.7 是 UFLS 与 Φ_sat 调谐拐点，可通过参数微调消除；第 1 轮成为 WHEN 的峰值是物理结构必然，要让第 k 轮成峰值，必须引入 τ 累积或 APT 潜伏机制。
